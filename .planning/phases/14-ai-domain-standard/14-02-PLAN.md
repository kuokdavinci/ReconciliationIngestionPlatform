    **Per WR-07: LLM provider created per-request → move to startup**

    In `src/api/__init__.py`:
    ```python
    from src.analysis.config import AnalysisConfig
    from src.analysis.provider import create_provider

    @asynccontextmanager
    async def lifespan(app: FastAPI) -> AsyncGenerator[None, None]:
        client = AsyncIOMotorClient(settings.mongodb_url)
        app.state.db = client[settings.db_name]
        app.state.mongo_client = client
        
        # Initialize LLM provider at startup
        app.state.llm_provider = create_provider(AnalysisConfig())
        
        await apply_indexes(app.state.db)
        yield
        client.close()
    ```
    
    In `src/api/insights.py`:
    - Replace `_get_llm_provider()` function that creates new instance per request:
    ```python
    def _get_llm_provider(request: Request) -> object:
        """Get the LLM provider from app state (created at startup)."""
        return request.app.state.llm_provider
    ```

    **Per WR-06: Redundant `except HTTPException: raise` blocks** (6 occurrences)
    
    Remove all bare `try/except HTTPException: raise` blocks. Each endpoint has the pattern:
    ```python
    try:
        partner = _validate_partner(partner)
        date = _validate_date(date)
    except HTTPException:
        raise  # REDUNDANT - remove
    ```
    
    Change to:
    ```python
    partner = _validate_partner(partner)
    date = _validate_date(date)
    ```
    
    The `_validate_partner` and `_validate_date` functions already raise `HTTPException` when validation fails. FastAPI's exception handlers will catch it. The bare re-raise blocks add no value. Remove them from all 3 endpoints (summary, discrepancies, daily report) where they appear.
    
    Keep the outer `try/except Exception as exc` blocks that catch unexpected errors and return 500 — those ARE necessary.
