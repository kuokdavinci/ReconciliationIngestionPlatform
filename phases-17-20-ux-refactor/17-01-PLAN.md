# Phase 17: Navigation Restructure + Data Intake Refactor

## Goal

Restructure the sidebar navigation so "Mapping Studio" is demoted to a Tools sub-group, and "Review Queue" is renamed to "Review Center". Rewrite the Data Intake landing to show a Partner Snapshot grid + a minimal Selected Partner Summary card.

## Plans

### Plan 1: Navigation restructure (`17-01-PLAN.md`)

**Files:** `frontend/app.js` (routes array, nav render)

**Changes:**
- Reorder primary nav: Data Intake, Review Center, Reconciliation, Automation
- Add a "Tools" sub-group in the sidebar containing Mapping Studio
- Rename "Review Queue" → "Review Center" everywhere in nav
- Update route mappings and hash-change handling
- Update page subtitle text for Review Center

**Verification:**
- Sidebar shows 4 primary + 1 sub-group with correct icons
- Clicking each nav item renders the correct view
- No stale "Review Queue" text in nav or page titles
- Mapping Studio still accessible from Tools group

### Plan 2: Data Intake — Partner Snapshot + Selected Partner Summary (`17-02-PLAN.md`)

**Files:** `frontend/app.js` (renderPartnerIntake), `frontend/styles.css`

**Changes:**
- Partner Snapshot: grid of partner cards showing partner name, overall status, latest file, file count, pending changes
- Clicking a partner card selects it and updates the detail section below
- Selected Partner Summary: compact dashboard card with partner name, status badge, 3 fact pills (runtime, latest file, review), copilot summary sentence, "Open Brief" primary action, "Upload file" secondary action
- Remove all evidence cards, safe checks, decision controls, mapping diagnostics from dashboard
- Remove `.intake-copilot-layout`, `.intake-compact-row`, `.intake-mini-indicators`, `.copilot-summary-card` CSS
- Add `.intake-dashboard-card`, `.intake-dash-facts`, `.intake-dash-copilot` CSS

**Verification:**
- Partner grid renders with correct data per partner
- Clicking a partner selects it and updates the dashboard
- Dashboard shows only: name, status, 3 facts, copilot line, Open Brief, Upload file
- No evidence, safe checks, or decision controls on dashboard
- Scannable in 5 seconds

### Plan 3: Backend intake API extensions (`17-03-PLAN.md`)

**Files:** `src/api/operations.py`

**Changes:**
- Ensure `/api/v1/operations/intake` returns all fields needed by Partner Snapshot (overallState per partner, latestFileSummary, fileCount, pendingProposalCount)
- Ensure `detail.statusHeader.primaryReason` is populated for the summary sentence
- Return `detail.pendingItems` with proper kind/title/reason for the brief Review step

**Verification:**
- API response includes all required fields
- Frontend renders correctly with new API data
- Backward compatible — no breaking changes to existing consumers

## Dependencies

- Plan 2 depends on Plan 1 (new nav must exist before intake UI is tested)
- Plan 3 can run in parallel with Plan 1

## Acceptance Criteria

- Data Intake is minimal and scannable in 5 seconds
- Navigation has 4 primary items + Tools group
- Mapping Studio is under Tools, not primary
- Dashboard does not show full evidence or decision controls
- All UI uses "Review Center", never "Review Queue" in nav
