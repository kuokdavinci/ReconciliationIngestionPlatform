# Plan 18-01: Backend — Separate decisionActions from secondaryActions

## Goal

Refactor `CopilotContextService._actions()` to return `decisionActions` as a separate array instead of mixing decision keys (approve_activate_next_runtime, approve_keep_current, reject_proposal) into `secondaryActions`. Add a `step` field to the context response. Ensure backward compatibility.

## Tasks

### Task 1: Split decision actions from secondary actions

In `src/services/copilot_context.py`, `_actions()` method:
- When `has_packet` is true: extract `approve_activate_next_runtime`, `approve_keep_current`, `reject_proposal` from secondary actions into a new `decisionActions` list
- Remove these three keys from `secondaryActions`
- Return the decision actions list from `_actions()`

### Task 2: Update `resolve()` to include `decisionActions` + `step` in context

In the `context` dict:
- Add `"decisionActions"` — the separated decision actions array (empty list when no proposal)
- Add `"step"` — string field: `"brief"` when healthy/monitor, `"review"` when has_packet/has_draft, `"decision"` when proposal exists

### Task 3: Verify backward compatibility

- `secondaryActions` stays but no longer includes decision keys
- `primaryAction` still returns the recommended action
- All existing frontend code that reads `secondaryActions` still works (no decision-key filtering needed after Plan 2)

### Task 4: Write tests

- Test context returns `decisionActions` only when proposal exists
- Test `decisionActions` is empty array when no proposal
- Test `step` field returns correct value per state
