# Phase 18: Copilot Brief 3-Step Modal

## Goal

Replace the current 4-step/5-step Copilot Brief with a focused 3-step modal: **Brief → Review → Decision**. Each step has exactly one purpose and one dominant primary CTA. Approve/Reject/Keep buttons appear only on the Decision step. After a decision, the modal closes, the dashboard refreshes, and a toast confirms the action.

## Plans

### Plan 1: Backend 3-step copilot context (`18-01-PLAN.md`)

**Files:** `src/copilot/context.py`, `src/copilot/schemas.py`

**Changes:**
- Add a `step` field to the copilot context response that maps to the 3-step flow:
  - `step: "brief"` — status, risk, headline, summary, 3 facts (runtime, file, review)
  - `step: "review"` — review item title, status, reason, impact, checks, proposed change
  - `step: "decision"` — recommendation, primary action, secondary actions, decision keys
- Ensure `proposal` in `evidence` includes all fields needed by Decision step
- Ensure `evidence.safeChecks` have human-readable labels (no internal keys)
- Return `decisionActions` array only when proposal exists
- Ensure `primaryAction` is always recommended (never a raw decision key for non-Decision steps)

**Verification:**
- API returns 3-step compatible context
- No internal keys leak into response
- `decisionActions` is empty when no proposal exists
- Backward compatible — old fields still present

### Plan 2: Frontend 3-step modal (`18-02-PLAN.md`)

**Files:** `frontend/app.js` (renderCopilotBrief), `frontend/styles.css`

**Changes:**
- `BRIEF_STEPS = ["Brief", "Review", "Decision"]`
- Step 1 (Brief): status + risk badges, one-line verdict, 3 compact fact rows (runtime, latest file, review). No buttons except Next.
- Step 2 (Review): if review item exists → show title, kind badge, status, reason, impact checks, proposed change. One contextual secondary: "Open Mapping Studio" (if mapping relevant). If no item → monitoring summary: "No review item waiting. Current runtime can continue. Latest file needs monitoring."
- Step 3 (Decision): recommendation block, dominant primary CTA (full-width), optional "Open full Review Center" link. Decision buttons (Approve & activate, Keep current runtime, Reject change) only if proposal exists.
- No approve/reject/keep buttons before Step 3.
- No Review Queue / Mapping Studio buttons repeated across steps.
- CSS: `.brief-hero`, `.brief-facts`, `.brief-review-item`, `.brief-checks`, `.brief-decision-recommendation`, `.brief-decision-cta`, `.brief-decision-links`, `.brief-decision-btn`

**Verification:**
- Brief has exactly 3 steps
- Each step has one clear purpose
- No decision buttons before Step 3
- Only one primary CTA per step
- Review Queue and Mapping Studio not repeated

### Plan 3: Confirmation, toast, dashboard refresh (`18-03-PLAN.md`)

**Files:** `frontend/app.js` (bindViewActions)

**Changes:**
- Decision actions (`reject_proposal`, `approve_activate_next_runtime`, `approve_keep_current`) automatically close brief after completion
- Set `state.briefOpen = false`, `briefStep = 0`, then call `render()`
- Toast message: "Proposal rejected." / "Proposal approved."
- Dashboard re-fetches from API and renders fresh data
- If `target.type` redirects to another view (review_queue, mapping_studio), still close brief first

**Acceptance:**
- After clicking Reject/Approve in brief Decision step: modal closes, toast appears, dashboard updates
- Brief context never shows stale data after action
- No double render or flash

## Dependencies

- Plan 1 must complete before Plan 2 (frontend needs correct API shape)
- Plan 3 depends on Plan 2 (needs modal structure to close)
- Data Intake refactor (Phase 17) should be complete so dashboard + brief integrate cleanly

## Acceptance Criteria

- Copilot Brief has exactly 3 steps: Brief, Review, Decision
- Each step has one clear purpose
- Runtime/latest file/review facts are not repeated in every step
- Review Queue summary is visible inside the brief for single-item cases
- Full Review Center is optional, not mandatory
- No more than one primary CTA per step
- No Approve/Reject/Keep before Decision step
- After decision, modal closes, dashboard refreshes, toast appears
