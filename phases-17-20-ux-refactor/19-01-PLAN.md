# Phase 19: Review Center + Mapping Studio

## Goal

Rename "Review Queue" to "Review Center" throughout the UI. Build the full Review Center workflow with validate/approve/reject/send-to-studio. Build Mapping Studio as a workspace accessed from Review Center or Data Intake when mapping work is needed. Implement bidirectional handoff between Mapping Studio and Review Center.

## Plans

### Plan 1: Review Center rename + full workflow (`19-01-PLAN.md`)

**Files:** `frontend/app.js` (renderApprovals, bindViewActions), `frontend/styles.css`

**Changes:**
- Rename "Review Queue" → "Review Center" in all page headers, titles, subtitles, buttons, toasts
- Route hash stays `review-queue` for backward compatibility; display name changes only
- Review Center shows:
  - Pending reviews list (packets + mapping configs)
  - Approved configs count
  - Closed decisions history (last 8)
  - Current partner filter
- Each pending review item supports:
  - **Validate** (runtime validation gates)
  - **Approve & activate** (approve + trigger reconciliation)
  - **Approve (keep current)** (approve without activating)
  - **Reject** (reject proposal)
  - **Send to Mapping Studio** (open studio with this item)
- Review item detail can be an inline expandable or drawer
- Scope override selector for packet approval (maintain existing scope logic)

**Verification:**
- Page header shows "Review Center" everywhere
- All 5 actions work on pending items
- Validate button calls `validate-runtime-packet` and shows result
- Approve/activate triggers reconciliation
- Send to Studio opens Mapping Studio with correct IDs

### Plan 2: Mapping Studio workspace (`19-02-PLAN.md`)

**Files:** `frontend/app.js` (renderSubmitSamplePage, mapping studio logic), `frontend/styles.css`

**Changes:**
- Mapping Studio is accessible from sidebar Tools group, Review Center (Send to Studio), and Data Intake (Open Mapping Studio)
- Workspace flow:
  - **Step 1:** Upload sample file + select sheet
  - **Step 2:** AI suggests field mappings (existing logic)
  - **Step 3:** Admin edits mappings manually
  - **Step 4:** Validate & test mapping schema (run mapping on sample, show output)
  - **Step 5:** Handoff confirmation → send to Review Center
- After handoff:
  - Show success toast
  - Navigate to Review Center
  - Review Center shows the new review item
- If opened from Review Center with a specific item ID, pre-load that item's mapping

**Verification:**
- All 5 steps work end-to-end
- Handoff creates a review item visible in Review Center
- Opened from Review Center pre-loads correctly
- Opened from Data Intake starts fresh

### Plan 3: Handoff integration + bidirectional nav (`19-03-PLAN.md`)

**Files:** `frontend/app.js`, `backend` (any API adjustments)

**Changes:**
- When Review Center sends a packet to Mapping Studio:
  - Store `reviewItemId` and `draftMappingId` in state
  - Navigate to `#mapping-studio`
  - Studio pre-loads the associated mapping config
- When Mapping Studio hands off:
  - POST to create/update review packet
  - Navigate to `#review-queue` (hash stays `review-queue`)
  - Toast: "Mapping submitted for review."
- When Data Intake "Open Mapping Studio" is clicked:
  - Start fresh (no pre-loaded item)
  - Toast: "Upload a file to begin."

**Verification:**
- Bidirectional handoff works (Review Center → Studio → back to Review Center)
- Studio pre-loads existing mapping when sent from Review Center
- Fresh Studio when opened from Data Intake
- No stale state between sessions

## Dependencies

- Plan 1 can run in parallel with Plan 2 (different files)
- Plan 3 depends on both Plan 1 and Plan 2 (needs both endpoints working)
- Phase 17 nav restructure should be done (Mapping Studio in Tools group)

## Acceptance Criteria

- "Review Center" replaces "Review Queue" in all UI copy
- All 5 review actions work (validate, approve-activate, approve-keep, reject, send-to-studio)
- Mapping Studio has 5-step flow: upload → AI → edit → validate → handoff
- Handoff creates review item visible in Review Center
- Bidirectional navigation works between Review Center and Mapping Studio
- No stale state when switching contexts
