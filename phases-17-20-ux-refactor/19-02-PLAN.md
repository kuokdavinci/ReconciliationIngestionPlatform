# Plan 19-02: Mapping Studio Workspace

## Goal

The Mapping Studio UI already exists with `renderSubmitSamplePage()` and step-based flow. This plan completes the 5-step workspace: upload → AI suggest → manual edit → validate → handoff. Ensure handoff creates a review item and navigates to Review Center.

## Tasks

### Task 1: Wire handoff button to POST review packet

The "Mark Ready for Review" / "Confirm Ready" button (`#studio-confirm-handoff-btn`) currently only toggles `handoffConfirmed` state in `bindViewActions`. Wire it to POST to the review packets API to actually create the review item.

```js
// In bindViewActions, handle studio-confirm-handoff-btn click:
const packetId = state.studio.draftMappingId;
if (!packetId) { showToast("No draft mapping to hand off."); return; }
fetch(`/api/v1/review-packets/from-mapping/${encodeURIComponent(packetId)}`, { method: "POST" })
  .then(r => r.json())
  .then(() => {
    showToast("Mapping submitted for review.");
    location.hash = "review-queue";
  })
```

### Task 2: Pre-load mapping when opened from Review Center

When `state.studio.reviewItemId` or `state.studio.draftMappingId` is set at navigation time (from `send-packet-to-studio` action), `openPacketInStudio()` already does this. Verify it fires correctly when navigating from the Review Center send-to-studio button.

### Task 3: Fresh start when opened from Data Intake

When `go-mapping-studio` is triggered from Data Intake side (not from Review Center), ensure `state.studio.*` is cleared before navigation.
