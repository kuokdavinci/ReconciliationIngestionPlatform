# Phase 20: Reconciliation View + Contextual Copilot Roles

## Goal

Build the Reconciliation view with tabs, filters, and AI Insights (Summary, Anomalies, Patterns, Recommendations). Contextualize Copilot per screen — Intake triage, Review analyst, Reconciliation analyst, Automation helper. After Approve & activate, trigger reconciliation automatically.

## Plans

### Plan 1: Reconciliation tabs, filters, AI Insights (`20-01-PLAN.md`)

**Files:** `frontend/app.js` (renderReconciliation), `frontend/styles.css`

**Changes:**
- Reconciliation view layout:
  - **Status tabs:** All / Matched / Unmatched / Error (filter by reconciliation status)
  - **Filters:** Amount range (min/max), date range (from/to)
  - **Results table:** transaction rows with status indicators
- AI Insights panel (segmented tabs above the table):
  - **Summary** — matched/unmatched counts, total amounts, percentages
  - **Anomalies** — AI-detected anomalous transactions with reasoning
  - **Patterns** — patterns in unmatched data (e.g., "80% unmatched come from bank X")
  - **Recommendations** — AI-suggested actions (e.g., "Update mapping config for payment type Y")
- Each insight tab fetches from the corresponding AI endpoint
- Maintain existing reconciliation data API (`/api/v1/reconciliation/results`)
- Insights API: `/api/v1/reconciliation/insights` with `type` param

**Verification:**
- Tabs filter results correctly
- Filters apply correct query params
- AI Insights panel loads data and renders each tab
- Table pagination works (existing limit param)
- Insights update when partner/date changes

### Plan 2: Contextual Copilot per screen (`20-02-PLAN.md`)

**Files:** `frontend/app.js`, `src/copilot/context.py`

**Changes:**
- Copilot context endpoint accepts a `screen` parameter: `intake`, `review`, `reconciliation`, `automation`
- Each screen returns tailored copilot data:
  - **intake** (Data Intake): triage-focused — status, latest file issues, pending changes
  - **review** (Review Center): approval-focused — pending count, risk summary, recommendation
  - **reconciliation** (Reconciliation): result-focused — anomaly count, matched %, top patterns
  - **automation** (Automation): job-focused — last failure reason, error context, retry suggestion
- Frontend passes `screen` param when fetching copilot context per route
- Copilot brief modal can be opened from any screen but content differs by screen
- Dashboard Copilot summary sentence reflects current screen context

**Verification:**
- Each screen returns different copilot context
- Brief modal content varies by screen
- No copilot context leaks between screens
- Automation screen shows job-relevant copilot info

### Plan 3: Auto-trigger reconciliation after approval (`20-03-PLAN.md`)

**Files:** `src/scheduler/reconciliation.py`, `src/api/copilot.py` (approve handler)

**Changes:**
- When `approve_activate_next_runtime` copilot action completes:
  - Backend schedules a reconciliation run for the partner + date
  - Response includes `postApproveRun` with status
- Frontend shows reconciliation result in toast: "Approve complete. Reconciliation started."
- If reconciliation completes synchronously, show results inline
- If async, show a note: "Reconciliation running — check the Reconciliation tab."
- Frontend reconciliation page fetches latest results on mount

**Verification:**
- Approve & activate triggers reconciliation
- Toast shows correct message
- Reconciliation page shows results after trigger
- No double-reconciliation on same partner+date
- Error state handled if reconciliation fails

## Dependencies

- Plan 1 can run in parallel with Plan 2
- Plan 3 depends on approve/activate flow from Phase 18 and Phase 19
- Reconciliation Insights API endpoint must exist (or be created)

## Acceptance Criteria

- Reconciliation has tabs, filters, and AI Insights with 4 tab types
- Copilot content is contextual per screen
- Auto-trigger reconciliation after Approve & activate
- No stale copilot context between screens
- Toast confirms reconciliation start after approval
